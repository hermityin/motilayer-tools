Motion Repeater

Version 1.1.1 · MotiLayer · Unity UI array animation

Motion Repeater repeats an animated UI object across a layout. A generated group stores its source animation and stagger, then exposes one Progress value for timing the whole result.

Install and open

Import the package into a Unity 6 project with Unity UI installed. Open Tools → MotiLayer → Motion Repeater. The supplied scene uses the Built-in Render Pipeline and standard Unity UI materials.

For the examples, open Examples/Scenes/MotionRepeaterShowcase.unity and enter Play Mode. Select one of twelve examples, pause, restart or use Previous and Next. Full source and eight Unity Presets are included.

Twelve animated examples

The showcase has two groups of six. Nested Compositions contains Scale Echo, Grid Pulse, Nested Squares, Nested Ribbon, Year Cascade and Nested Type Field. Layout Studies contains Ring Bloom, Spiral Flow, Bezier Path, Radial Burst, Hexagon Rings and Luminance Portrait.

Select an example in the left-hand list. Pause, restart or move between examples with Previous and Next. Each example keeps its own clip, source data and nested controllers; the player samples that clip and evaluates the composition at the same time. The framing objects only fit the animation into the presentation area.

Original source objects remain available inside the example hierarchies. Authoring sources that were left visible outside the composition are hidden with a CanvasGroup in the showcase. The generated copies, timing and gradients are preserved.

The examples demonstrate finished motion rather than one example for every layout. Grid, Ring, Path, Spiral, Radial, Hexagonal, Scatter and Sprite Shape remain available in the tool.

Make an animated array

  1. Animate a UI object under an Animator or Animation root using a writable Animation Clip. Give objects unique sibling names; avoid / in names.
  2. Assign Source Object, Animation Clip and Animation Root in Motion Repeater. The root must be the object relative to which the clip's paths were recorded.
  3. Set Start Time and End Time in seconds. Use Animation Window copies the open clip and playhead, then the panel keeps that context while you edit settings. Insert At sets where the generated progress curve begins.
  4. Choose the layout, playback order, stagger, source time scale and optional overrides. A blank clip creates a static array.
  5. Click Start Preview. The source stays active but is hidden visually after preview copies are created. Stopping preview, closing the window or saving the scene restores it. Saving a scene ends the temporary preview.
  6. Enter the array name above Preview. Click Generate Array (Progress Control). The generated hierarchy stays in the scene; its Time Controller gets a Progress curve in the assigned clip. The source is restored.

Generated source clips are saved under Assets/MotionRepeaterData. Keep these assets with the arrays that reference them. Include them when moving a prefab or scene to another project. An exported prefab's dependencies must include the source clips.

Time remapping

Select the generated group and find Motion Repeater Time Controller. Progress (0–1) is the whole composition's time. At 0, each element is at the start of its source range; at 1, every element has reached its end. The composition duration includes stagger.

Use Add Property in Unity's Animation window to keyframe Progress. The generation step already creates a linear 0-to-1 curve. Move those keys to change duration; edit their tangents for easing. Hold Progress to freeze the array or decrease it to play backwards. Progress is clamped to 0–1. Loop through an Animator clip's loop setting or repeat the Progress curve; the component does not advance a clock on its own.

The source animation is captured when generating. The selected interval includes existing keys; include the required keys at both interval boundaries. Editing the original clip later does not update the array automatically; regenerate to capture the change. Position, scale and color before the first delayed frame follow the source's start state, so put any entrance invisibility into that first state.

The Time Controller samples local clips and then updates layout controllers. Top-level drivers evaluate nested drivers in hierarchy order. Unchanged progress does not repeatedly resample source clips; layout parameters can still respond to their own changes.

Nested arrays

Generate the first array and animate its Progress. Use that group as the source of another array, with a clip containing its Progress curve. Each outer copy retains its inner composition and timing data. Repeat this process for additional levels.

Keep one animation owner for a driven subtree. An independent Animator on an inner object can compete with the Time Controller for the same properties. More levels still mean more GameObjects and animation sampling; a short main timeline does not make rendering cost disappear.

Layout reference

Layout Placement Ordering
Grid Rows, columns and spacing Sequential, random, from center, by row or column
Ring Radius, start angle, spread and facing Around the ring, paired inward/outward and random
Path Fixed control points; linear or Bezier interpolation Along the path, center-based and random
Spiral Turns, inner/outer radii, winding and spread Along the spiral or random
Radial Rays, elements per ray, inner radius and radial spacing By ray, inner to outer, sweep around center or random
Hexagonal Center plus concentric hexagonal rings Ring by ring, by row or random
Scatter Count, seed and rectangular width/height Random or distance from a reference point
Sprite Shape Samples a sprite or a grid of sprite-sheet frames Spatial order or random; hidden frame cells keep their indices

Playback order determines delay. Index order controls how per-element offsets are assigned. Reverse changes the selected ordering. Counts and ordering are established at generation; continuous layout parameters exposed on the generated controller can be animated.

Paths and facing

Set the number of control points before generation. Drag blue position handles in Scene view or animate the generated points' component properties. Bezier handles use angle and length. They are linked by default; expand the advanced options to enable manual or independent handles.

Path Offset moves the array along the path. 100% is one full path length. With Loop Along Path, positions wrap; an open path jumps between its endpoints. Without looping, positions beyond the path continue along the endpoint tangent. Negative offsets are allowed. Align to Path and Rotation Offset control facing. Radial arrays can face along each ray with an angular offset; rings and spirals have their own orientation choices.

Sprite shapes and sprite sheets

Assign a sprite. Sampling uses cell centers, so finer grids capture more detail but create more objects. For a sheet, use one sprite containing the whole sheet and enter frame columns and rows. Frames are read from the top-left, across each row, using all cells. Animate frame Progress to move through the sequence.

The generated array reserves the union of visible cells across all frames. Elements keep their index and object identity; cells that are not visible in a frame are hidden instead of destroyed. This preserves timing and Index Offset assignments.

Mask Channel selects Alpha or Luminance; their thresholds are mutually exclusive. Luminance mode still ignores fully transparent pixels. Invert Luminance reverses the brightness reading. Scale by Luminance maps dark and light values to the two scale multipliers. Opacity by Luminance maps them to alpha multipliers.

Luminance scale is applied on the element wrapper, separately from the source's animated scale and Index Offset. Luminance opacity multiplies through a CanvasGroup, preserving Image color alpha. If a source CanvasGroup ignores parent groups, affected elements skip the luminance opacity effect. Changing the sprite, frame grid or sampling density requires regeneration; pixels are sampled during authoring, not every runtime frame.

Color, sprites and target objects

Use gradients, random colors or sprite assignment to vary copies. The Target Objects section is collapsed by default. Expand it to choose exact objects within the source; only Images on those objects are affected, not their child Images. Add more targets if needed. Collapse it to return to the default target without discarding the list.

Index Offset has a matching target section for position, rotation and scale. Children inherit the selected objects' transforms normally. Target lists are authoring settings and cannot be changed on a generated component. Choose them before generation.

The Color Controller records a gradient pose with Gradient → Keyframes. Set the Animation window time, edit the gradient and record; repeat at another time. Only one Gradient Time float curve is added to the clip. Gradient poses stay on the component and interpolate between saved times. The component's time slider, measured in seconds, can hold, reverse or retime the color sequence independently of the main Progress curve. Editing a stored pose affects every animation using that composition.

Keyframes → Gradient reads the current gradient back for editing. Clear Current Frame removes the selected time key and its unshared stored pose; Clear All removes the component's gradient sequence and the current clip's Gradient Time curve. Both support Undo. Existing color curves in migrated internal clips are left intact. The new gradient overrides only the chosen Images after nested source animation has been sampled; sprite-shape opacity continues to multiply through its separate CanvasGroup.

Undo, presets and Reset

Use Unity Undo for panel edits and generation. The Presets control saves the tool's settings as a native Unity Preset. Source objects, animation context and preview objects are not reusable preset content. Right-click the window header and choose Reset to restore default tool settings; Undo can restore the previous settings.

Convert an older scene

Open the scene and choose Tools → MotiLayer → Motion Repeater — Migrate Current Scene. The utility creates a saved scene copy and clip copies in Assets/MotionRepeaterMigrationBackup_<timestamp> before converting anything. Preview is stopped first. It migrates curves below array roots into internal clips and replaces them with Progress curves, working from inner arrays outward. Empty, unanimated Offset wrappers are removed and binding paths are adjusted.

Existing unique animation curves are retained internally to preserve hand edits. Migration reorganizes them; it does not infer a shared source or compress every old clip. A group animated by several clips gets an Animation selector. Groups with no animation stay static. Clips shared by several animation roots require separate clip assets before conversion. Keep the backup until you are happy with the result. The backup scene still references the original clip assets; restoring it also requires restoring the backed-up clip contents.

Requirements and scope

Unity 6000.0.26f1, Windows and Unity UI 2.0.0 are the release environment. The 2D Sprite package is useful for slicing sprites but is not an external Asset Store dependency. This release does not claim verification on URP, HDRP or other platforms.

This is a uGUI authoring and runtime-component tool, not a particle system or GPU-instanced 3D cloner. Source objects remain GameObjects. Count, hierarchy depth and the number of animated properties affect performance. Animation Events, humanoid/root motion and additive Animator-layer blending are outside the supported composition workflow. Do not rename or reparent generated internals without also repairing their animation paths.
